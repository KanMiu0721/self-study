# `<video>`元素:
<video>元素可以轻松嵌入视频
```
<video src="rabbit320.webm" controls>
  <p>
    Your browser doesn't support HTML video. Here is a
    <a href="rabbit320.webm">link to the video</a> instead.
  </p>
</video>
```

1. src:
src（源）属性包含你想嵌入的视频路径

2. controls:

用户必须能够控制视频和音频播放。必须使用controls属性来包含浏览器自身的控制界面，或者使用相应的JavaScript API构建界面。至少，界面必须包含启动和停止媒体以及调节音量的功能

3. `<p>`:
这被称为备援内容——如果访问该页面的浏览器不支持`<video>`元素，我们会显示这些内容，从而为较旧的浏览器提供备援。这可以是任何东西;在这种情况下，我们提供了视频文件的直接链接，这样用户无论用什么浏览器，都能以某种方式访问视频

## 使用多种源格式以提高兼容性:

### 媒体文件内容:
像 OGG、WAV、MP4 和 WebM 这样的格式被称为**容器格式**。它们定义了构成媒体的音频和/或视频轨道存储结构，以及描述媒体、用于编码通道的编解码器等元数据

每个浏览器不仅支持不同的容器文件格式，还支持不同的编解码器选择。为了最大化网站或应用在用户浏览器上运行的可能性，你可能需要提供每种媒体文件的多种格式
```
<video controls>
  <source src="rabbit320.mp4" type="video/mp4" />
  <source src="rabbit320.webm" type="video/webm" />
  <p>
    Your browser doesn't support this video. Here is a
    <a href="rabbit320.mp4">link to the video</a> instead.
  </p>
</video>
```
这里去掉了`<video>`src属性，而是包含了指向自己来源的独立`<source>`元素。在这种情况下，浏览器会先播放`<source>`元素，播放它有编解码器支持的第一个元素。如今，只要包含WebM和MP4资源，就能在大多数平台和浏览器上播放视频

每个`<source>`元素也有一个type属性。这是可选的但建议使用。type属性包含`<source>`指定文件的MIME类型，浏览器可以使用该type立即跳过不理解的视频。如果没有type，浏览器会加载并尝试播放每个文件，直到找到一个可用的，这显然耗时且浪费资源

## 其他`<video>`特色:
```
<video
  controls
  width="400"
  height="400"
  autoplay
  loop
  muted
  preload="auto"
  poster="poster.png">
  <source src="rabbit320.mp4" type="video/mp4" />
  <source src="rabbit320.webm" type="video/webm" />
  <p>
    Your browser doesn't support this video. Here is a
    <a href="rabbit320.mp4">link to the video</a> instead.
  </p>
</video>
```
- width and height:
可以用这些属性或CSS来控制视频大小。在这两种情况下，视频都保持其原生的宽高比——即宽高比。如果设置的尺寸不维持宽高比，视频会水平增长以填满空白，未填充的空白默认会被赋予纯色背景色

- autoplay:
让音频或视频立即开始播放，而页面其余部分正在加载。建议不要在网站上使用自动播放视频（或音频），因为用户可能会觉得非常烦人

- loop:
每当视频（或音频）结束时，它会重新开始播放

- muted:
这会导致媒体默认关闭声音播放

- poster:
视频播放前将显示的图片URL。它旨在用作启动画面或广告画面。

- preload:
用于缓冲大文件;它可以取三种数值之一：
1. "none"不会缓冲文件
2. "auto" 缓冲媒体文件
3. "metadata" 只缓冲文件的元数据

# `<audio>`元素：
`<audio>`元素的工作原理与`<video>`元素相同，但有一些细微差别
```
<audio controls>
  <source src="viper.mp3" type="audio/mp3" />
  <source src="viper.ogg" type="audio/ogg" />
  <p>
    Your browser doesn't support this audio file. Here is a
    <a href="viper.mp3">link to the audio</a> instead.
  </p>
</audio>
```
这比视频播放器占用的空间更小，因为没有视觉元素——只需显示控制按钮即可播放音频

与HTML视频的其他区别如下：

- `<audio>`元素不支持width/height属性——没有视觉组件，因此没有可以分配宽度或高度。

- 它也不支持poster属性——同样没有视觉成分。

# 显示视频文本轨:
WebVTT 是一种用于编写包含多字符串文本及元数据的格式，例如视频中每个文本字符串应显示的时间，甚至是有限的样式/位置信息。这些文本字符串称为提示，提示有多种不同用途

最常见的提示有：
- subtitles:

为不理解音频中所说内容的人翻译外语。

- timed descriptions

媒体播放器应通过口音朗读文本，以向盲人或其他视障用户描述重要的视觉内容。

一个典型的WebVTT文件看起来像这样：
```
WEBVTT

1
00:00:22.230 --> 00:00:24.606
This is the first subtitle.

2
00:00:30.739 --> 00:00:34.074
This is the second.

…
```


要让这些内容与HTML媒体播放一起显示，需要：

1. 将其保存为.vtt文件，存放在服务器可以提供的地方（见下文），比如与HTML文件相同的目录。
2. 链接到带有`<track>`元素的.vtt文件。`<track>`应放在`<audio>`或`<video>`，但要经过所有`<source>`元素之后。
3. 使用kind属性来指定提示是subtitles、captions还是descriptions
4. 使用srclang告诉浏览器你用的是哪种语言写字幕。最后，添加一些label帮助读者识别他们所寻找的语言
```
<video controls>
  <source src="example.mp4" type="video/mp4" />
  <source src="example.webm" type="video/webm" />
  <track kind="subtitles" src="subtitles_es.vtt" srclang="es" label="Spanish" />
</video>
```

# 与用户互动:
按钮通常使用 HTML` <button> `元素创建（有时也用 `<input>` 元素创建，type属性设置为如button或submit）。这些按钮是通用的——可以连接它们来触发任何功能，仅限于想象力和编程技能

表单通过诸如`<form>`、`<label>`、`<input>`和`<select>`等元素创建。表单元素可以用来创建比简单按钮更复杂的控制——例如，一个包含多个选项的下拉菜单，允许在不同主题中选择用户界面元素

然而，关键是，它们还可以用于创建表单，供用户在需要向网站服务器提交信息时填写

# 按钮:
按钮在网络上有几个主要用途。首先，它们用于触发功能，这在创建界面控件时非常有用。最简单的按钮是用以下代码实现的：
```
<button>Press me</button>
```
出现在标签之间的文字会在按钮内部渲染，浏览器会给它一些基本样式，使其默认看起来和表现得像按钮

## 形态的解剖结构
基本形式包含三点：

- 一个`<form>`元素，包裹所有其他表单内容。标签内的任何表单控件都是同一表单的一部分，提交表单时会包含它们的数据

- 一对或多对，分别由一个`<label>`元素和一个表单控制元素（通常是`<input>`元素组成，但也有其他类型，例如`<select>`）：

       1. 表单控制元素允许用户选择或输入一些数据，这些数据将在表单提交时发送到服务器
       2. `<label>`元素为表单控件提供一个识别标签，描述应输入的数据

- 一个`<button>`元素，用于提交表单

```
 <form action="./submit_page" method="get">
      <h2>Subscribe to our newsletter</h2>
      <p>
        <label for="name">Name (required):</label>
        <input type="text" name="name" id="name" required />
      </p>
      <p>
        <label for="email">Email (required):</label>
        <input type="email" name="email" id="email" required />
      </p>
      <p>
        <button>Sign me up!</button>
      </p>
    </form>
```

# `<form>`元素

`<form>`元素作为表单的外包，将所有表单控件归组其中。当按下`<button>`时，表单控件代表的所有数据都会提交到服务器。该元素可以有许多属性，但在示例中包含的两个最重要的属性如下：

- action： 包含一条通往我们想发送提交表单数据的页面的路径，以便处理。在提交表单后，会在网址中看到包含的内容。还会收到404错误回复，因为./submit_page页面实际上不存在，但目前没关系

- method： 指定想用来向服务器发送表单数据的数据传输方式。暂时别太担心;get值使数据作为附加参数发送到URL末尾
  
查看提交的数据
1. 进入另一个标签页的示例，尝试输入“Bob”这个名字和一个“bob@bob.com”的电子邮件地址。
2. 按下 `<button>`
action和method属性使表单数据以以下URL形式提交：
```
/some/url/submit_page?name=Bob&email=bob%40bob.com
```
## 结构形式:
可以在元素中包含任何你喜欢的HTML元素，来结构化表单元素本身，并提供容器用CSS来定位样式等

还可以把每个输入/标签对和提交按钮放在一个独立的`<p>`里，这样每个都会出现在不同的行里。这些元素默认都是内联的，这意味着如果不这样做，它们都会放在同一行上

有一个专门用于将形式元素分组的元素，称为`<fieldset>`。这在某些情况下非常有用，比如复杂表格以及将多个复选框和单选按钮分组时

# `<input>`元素:

`<input>`元素代表表格中输入的不同数据项
```
<input type="text" name="name" id="name" required />
```
- type： 指定要创建的表单控制类型。表单控制有许多不同类型，从简单的文本字段到单选按钮、复选框等。text会渲染一个基本的文本字段，可以接受任意值
- name(提供给服务器，可重复)： 指定数据项的名称。表格提交后，数据会以名称/值对的形式发送。在每种情况下，名称等于该属性值，值等于文本字段中输入的文本
- id（提供给前端代码，唯一）： 指定一个可用于识别元素的ID。在这种情况下，它用于将形式控制与其关联
- required： 指定必须在提交表单元素前输入一个值。这只应该设置在你需要的输入上，而不是可选字段

 要注意，有些输入类型通常不会直接从输入字段的文本中获得其值。例如，`<input type=“color”>`渲染一个颜色选择器控件，而`<input type=“radio”>`渲染一个可以选择或不选择的单选按钮控件 

 对于单选按钮，通常需要提供如果在特定属性中选择时提交的值。注意你可以在输入类型上指定属性，比如text和color——效果是该值在首次渲染时会预先填充到表单字段中
 
##  required以及实际的属性value
试着编辑表单，把value="Bob"写在第一个输入里。当重新加载代码时，会看到第一个字段默认输入了一个“Bob”的值

## 专用文本字段输入
有几种专门的文本字段输入类型专门用于处理特定类型的数据——`<input type=“number”>`，`<input type=“password”>`，`<input type=“tel”>`等。

# `<label>`元素
`<label>`元素为表单控件提供了识别标签，描述应输入的数据。可以在元素里放任何你喜欢的文本内容，但它们应该准确描述表单控制对应的数据。关联通过赋予表单控件一个属性，然后赋予元素一个与控件值相同的属性来创建
```
<label for="name">Name (required):</label>
<input type="text" name="name" id="name" required />
```

## 显式与隐式形式标签:
上面看到的表单标签样式称为显式表单标签——控制和标签之间的关联通过属性显式实现。也可以通过将控件嵌套在标签内来实现隐式表单标签
```
<label>
  Name (required):
  <input type="text" name="name" required />
</label>
```

# `<button>`元素：
当元素中包含`<button>`元素时，其默认行为是提交表单，前提是没有无效数据，导致提交被客户端表单验证阻断

其他按钮行为可以通过元素属性来指定

- `<button type="submit">`明确声明按钮应表现为提交按钮。其实不需要特别声明，除非在form里面包含了其他按钮，并且想明确表示提交按钮是哪一个

- `<button type="reset">`创建一个重置按钮——这会立即删除表单中的所有数据，使其恢复到初始状态。**不要使用重置按钮**——它们在网络早期很流行，但通常比起帮助更让人烦躁

- `<button type="button">`创建一个与元素外指定按钮相同的行为按钮。正如之前看到的，它们默认完全没有任何功能，需要JavaScript来赋予它们功能

## 单选按钮:
“选择酒店房间类型”按钮是通过`<input type=“radio”>`控制实现的。这些按钮显示为一组按钮控制，一次只能选择其中一个——不能同时选择多个
```
<fieldset>
  <legend>Choose hotel room type:</legend>
  <div>
    <input
      type="radio"
      id="hotelChoice1"
      name="hotel"
      value="economy"
      checked />
    <label for="hotelChoice1">Economy (+$0)</label>

    <input 
      type="radio" 
      id="hotelChoice2" 
      name="hotel" 
      value="superior" />
    <label for="hotelChoice2">Superior (+$50)</label>

    <input
      type="radio"
      id="hotelChoice3"
      name="hotel"
      value="penthouse"
      disabled />
    <label for="hotelChoice3">Penthouse (+$150)</label>
  </div>
</fieldset>
```
radio输入类型大体上与test输入类型相同，但有一些不同：

- 每组单选按钮的**name属性必须包含相同的值**，才能将它们关联为一个集合。如果它们包含不同的数值，实际上它们将是独立的集合，提交时的数值也不同

- 你必须为每个单选按钮包含一个包含要提交值的**value属性**。提交的值将是一个名称/值对，即name=value（如hotel=superior）

>如果你在 `<input type="radio">` 中省略了 value 属性，浏览器会默认把值设为字符串 "on"

- 每个单选按钮应该描述该具体的数值选择，而不是选择的整体数值。描述整体值选择的首选方式是将它们包裹在`<fieldset>`中，将包含描述的`<legend>`元素作为子节点

>应用了checked属性——这会导致页面首次加载时选择该按钮。这意味着总是会选择一个选项，取消选择单选按钮时必须选择另一个

### 禁用表单控制:
第三个单选按钮上设置了disabled属性。这会导致渲染后的控件变成灰色且无法选择。这在许多通常有选项但现在还不行的情况下非常有用

`<fieldset>`元素也可以接受disabled属性——这会导致字段集内的所有表单控件被禁用

## 复选框(多选)

```
<fieldset>
  <legend>Choose classes to attend:</legend>
  <div>
    <input type="checkbox" id="yoga" name="yoga" />
    <label for="yoga">Yoga (+$10)</label>

    <input type="checkbox" id="coffee" name="coffee" />
    <label for="coffee">Coffee roasting (+$20)</label>

    <input type="checkbox" id="balloon" name="balloon" />
    <label for="balloon">Balloon animal art (+$5)</label>
  </div>

```
value用法同上（默认为on）

# 下拉菜单：
```
<label for="transport">How are you getting here:</label>
<select name="transport" id="transport">
  <option value="">--Please choose an option--</option>
  <option value="plane">Plane</option>
  <option value="bike">Bike</option>
  <option value="walk">Walk</option>
  <option value="bus">Bus</option>
  <option value="train">Train</option>
  <option value="jetPack">Jet pack</option>
</select>
```
该元素包裹了所有不同的值选择。它就是设置将控件与其标签关联的属性，以及设置要提交数据项名称的属性

数据项的每个可能值都由嵌套在元素内部的一个元素表示。每个元素可以选择一个value属性，该属性指定如果从下拉列表中选择该选项，则需提交value的值。如果你不指定，`<option></option>`标签内的文本将作为值

# 多行文本输入字段
多行文本输入字段通过`<textarea>`元素创建：
```
<label for="comments">Any other comments:</label>
<textarea id="comments" name="comments" rows="5" cols="33"></textarea>
```
它们的行为与元素相同，只是允许输入多行文本。rows属性默认指定文本区域的行数，cols属性表示文本区域默认的列数。如果未指定，使用的值为 cols="20"和rows="2"
